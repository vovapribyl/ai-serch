# Ошибки фото и повтор публикации: результат реального пакета

Дата:2026-10-15. Статус: **EXECUTED / OK**.

Выполнены все пять фаз [плана](error-retry-runtime-plan.md) по общему пакетному допуску владельца, без промежуточных запросов разрешения. Один собственный временный контур,137,139с с подготовкой и очисткой. Рабочая БД, корпус и Web не менялись.

## Найденный дефект и исправление

До ML новый тест воспроизвёл ошибку native-адаптера: повреждённое изображение с корректными frozen bytes/SHA вызывало общий BuildStop. Это мешало исполнению FR-037/038 — сохранить ошибку фото и продолжить независимые фото.

В ManifestImageStore добавлен SourceImageDecodeError как subtype прежнего BuildStop, только для ошибки декодирования уже проверенных байтов. Старый build-процесс по-прежнему видит BuildStop(INVALID_SOURCE). NativeStageDriver переводит только новый subtype в PhotoProcessingError(INVALID_IMAGE). Hash/path/size/общие файловые ошибки не превращаются в recoverable photo errors. Политики ядра, модельные профили и зависимости не менялись; перевод ошибки остался во внешнем адаптере по выбранному правилу book-guidance/Clean Architecture.

TDD: новый тест malformed image сначала упал по BuildStop вместо PhotoProcessingError; тест SOURCE_HASH_MISMATCH уже проходил. После исправления оба прошли. Выборка image-store/image-processor/build-composition/stage-payload —65passed за1,96с. Полная replenishment-регрессия —510passed/28файлов/0failures-errors-skipped за197,941с. Выборки пересекаются, их нельзя складывать как575уникальных случаев. Ruff/format/diff прошли.

## Как создана ошибка публикации

Только в принадлежащей тесту БД перед фазой F установлен BEFORE INSERT trigger на catalog_snapshots: фиксированный SQLSTATE23514. Транзакция создания нового snapshot откатилась; адаптер сохранил отдельную неуспешную попытку публикации. Прежний active snapshot остался неизменным.

Перед P удалены только созданные тестом trigger и function. Retry использовал READY-редакцию и сохранённые ML-артефакты. После P и I ни одного stage/worker/checkpoint event, никаких новых checkpoint/file/vector-value fingerprints. В истории4publication_attempts:3SUCCEEDED и1ожидаемаяFAILED. Это инъекция проверяемого отказа транзакции, не имитация OOM, потери диска или аварии PostgreSQL.

## Очистка и ограничения

Независимая OS/container проверка подтвердила0собственных host/worker/viewer и процессов их групп,0B1/probe-контейнеров, отсутствие socket, secret env и всех пяти target descriptor. Все5грантов использованы. Собственная БД удалена; private logs/JUnit/inputs/checkpoints/aggregate и frozen commands сохранены. Они не дают готового RESUME без БД.

Повторы T/P/I были заранее запланированными явными командами, не автоматическим retry после неожиданной ошибки. В ходе подготовки private_json отказал чтению selection из общего/tmp из-за прав родителя; использовано обычное чтение ранее выбранного metadata-файла. Опечатки SQL генератора исправлены и синтаксис проверен до DB/ML; исходные runtime результаты не переписывались.

Review не проводилось. Нет установки dependencies, рабочей активации, изменения модели/лимитов, commit/push/merge. Качество поиска, сотни фото и рабочий cutover остаются непроверенными. Исторические resource STOP/первый межфазный AssertionError не воспроизвелись и не объявлены устранёнными этим пакетом.
