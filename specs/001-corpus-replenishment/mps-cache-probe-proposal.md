# Проверка освобождения MPS-кеша между фото

Дата: 2026-10-14. Статус: **EXECUTED / OK**.
Владелец разрешил подготовить [проверку гипотезы](load-diagnostics-report.md#следующая-проверяемая-гипотеза).
На этапе подготовки изменение проверено без моделей. Затем владелец отдельно разрешил
замороженный пакет; результат исполнения приведён ниже.

## Вопрос эксперимента

Снизится ли удерживаемая память MPS driver, если после каждого успешно
завершённого вызова локализации фото освобождать неиспользуемый кеш allocator?
Базовая проба de3c9c6e дала пять READY-товаров и 5,83 GiB driver при примерно
1,16 GiB живых тензоров на границах операций. Доли кеша и MPS/MPSGraph неизвестны.

## Единственное изменение

В замороженном runtime binding включено empty_cache_after_photo=true.
Для него обязательно load_diagnostics=true; без этих настроек поведение прежнее.
Несовместимый или нетипизированный флаг отклоняется при проверке control,
до SDK import. Очистка выполняется только в локализаторе, не в encoders.

После успешного CandidateIBinding.__call__ вызывается torch.mps.empty_cache().
Один вызов на фото, после первого и возможного второго ROI-прохода,
до возврата HTTP-ответа контроллеру. Исходный результат передаётся дальше.
Если локализация бросила исключение, очистка не вызывается, исходная ошибка сохраняется.
Ошибка самого empty_cache не скрывается: вызов фото не объявляется успешным,
а диагностические события фиксируют error. Детали остаются в приватном журнале.

SAM features не сбрасываются, модель не выгружается, gc не вызывается,
дополнительный synchronize не добавлен. Веса, prompt, thresholds, resize,
dtype, device и seed не менялись. Пороги безопасности и правила публикации прежние.
Ожидаемый эффект не заявляется как установленный: API освобождает неиспользуемый
кеш allocator, но не обещает удалить все выделения framework/MPSGraph.

## Как проверим результат

- Для каждого успешного фото нужны before/after события mps.empty_cache;
  при пяти успешных фото ожидаются пять пар.
- Сравним driver и live до/после очистки каждого фото, остаточную память между
  фото и наблюдённый максимум по всей стадии. Выведем фактические изменения в байтах,
  а не только итоговый статус. Границы операции не показывают каждый короткий пик.
- Сопоставим число регионов и SHA-256 crop/mask bytes с успешным de3c9c6e.
  Для тех же пяти фото базовый результат — 32 региона и 64 crop/mask artifacts.
- Проверим сохранённые vectors, photo/revision outcomes, checkpoints,
  publications и состав последнего active snapshot в собственной временной БД.
- Отдельно учтём длительности вызовов и очистки, CPU, RSS, pressure и swap.
  Различие общего времени двух проб не является доказательством ускорения.

Если driver не снизится, гипотеза не подтверждена. Если результаты локализации
изменятся, эксперимент нельзя считать сохранением прежнего поведения.
Если сработает ресурсный guard, фиксируем частичный результат и останавливаемся.
Ни один из исходов не разрешает автоматический повтор, сброс SAM features,
изменение разрешения или повышение потолков.
