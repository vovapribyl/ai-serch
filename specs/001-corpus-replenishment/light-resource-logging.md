# Лёгкий журнал ресурсов и стадий

2026-10-15. STANDARD. Владелец согласовал лёгкий режим после обсуждения стоимости
логирования. Это дополнение к [журналу операций](operation-logging.md) и
[терминальному монитору](light-monitoring.md), без изменения правил обработки.

## Что добавлено

При `load_diagnostics: true` native worker начинает журнал до импорта Torch.
В нём остаются события начала, результата и ошибки операций, а во время долгого
вызова отдельный поток делает замер примерно раз в секунду. Теперь можно
увидеть рост ресурсов между началом и завершением операции, включая её падение.

Отдельные границы: Torch/LangSAM import, SAM/Grounding DINO load/predict,
localizer pass/photo, encoder load/photo и включённая ранее очистка MPS cache.
Границы crops/checkpoint/publication и исходы фото по-прежнему отражаются
существующим controller operation log; новая реализация не дублирует его.
Время между before/after включает диагностические накладные расходы.

Сохраняются RSS/CPU собственных процессов, MPS live/driver после импорта Torch,
pressure, занятый swap и системные VM-показатели. До SDK значения MPS отсутствуют
(UNKNOWN), а не изображают измеренный ноль. Whole-host swap нельзя целиком
приписывать worker. Неполные метрики отмечаются `measurement_ok: false`.

## Включение и частота

В новом frozen runtime binding:

```json
{
  "load_diagnostics": true,
  "diagnostic_interval_seconds": 1
}
```

При включённой диагностике отсутствие interval означает1секунду; значение0,5
предназначено для подробной диагностики. Другие значения отвергаются доSDK.
`load_diagnostics: false` либо отсутствие флага сохраняет прежний opt-in режим:
новый worker diagnostic log не создаётся. Операционный журнал и resource guard
при этом управляются своими существующими механизмами.

Worker периодически пишет не чаще заданного интервала после предыдущего замера;
сбор показателей тоже занимает время. Записи на границах операций добавляются
независимо от этого интервала. Controller resource diagnostics остаются около1Гц.
Новый параметр не меняет частоту обязательной защитной telemetry.

Binding/code hashes изменяются при подготовке новой версии пакета. Старые
consumed grants, frozen snapshots и уже выполнявшиеся стенды не обновляются
этим изменением и не являются разрешением повторить ML-прогон.

## Хранение и завершение

У worker — `load-events.jsonl`, до двух предыдущих файлов `.1.jsonl`/`.2.jsonl`,
каждый не больше min(max_wire_bytes,1MiB). Controller `load-resources.jsonl`
получил такую же ротацию. Максимум3MiB на один diagnostic sink, а не на всю
историю проекта: количество workers/runs учитывается отдельно общим storage guard.
Приватные директории700, файлы600, запись максимум4096bytes.

После штатного завершения `.status.json` содержит incomplete, число ротаций
и history_truncated. Последний признак означает, что старейшие события уже
удалены по лимиту. bytes_written относится к текущему файлу. После SIGKILL
финальная сводка может отсутствовать; это UNKNOWN, не подтверждение полноты.
Записи fsync сохраняются, но журнал не гарантирует сохранение события,
которое ещё не успели записать.

Периодический поток завершается вместе с контекстом worker. Ошибка записи
не подменяет результат модели; если sink вообще не удалось открыть, обработка
продолжается без него. Исключение — ранее включённый эксперимент
`empty_cache_after_photo: true`: для него сохранено прежнее требование доступного
диагностического sink, поэтому ошибка открытия приводит к отказу доML.
Отсутствие журнала не трактуется как успешная обработка.
Защитный watchdog не зависит от диагностического потока и продолжает применять
прежние resource/freshness/deadline limits. Короткие пики между замерами
всё ещё могут быть пропущены.

Фото, векторы, тексты исключений, SQL, secrets и исходные товарные identifiers
в эти журналы не добавляются. Нового сервера и фоновой службы нет.

## Проверка стоимости

Модельно-свободная проба текущей реализации:10,052с ожидания,9периодических
замеров/11записей,5616bytes журнала. CPU процесса вместе с его служебными
sampling commands —0,225с; сумма длительностей замеров0,219с, максимальный
замер0,021с. incomplete=false, diagnostic thread завершён, MPS доSDK UNKNOWN.

Это один наблюдаемый запуск без ML на текущем Mac. Его нельзя выдавать за
измеренное замедление ML на2%: CPU sampling, ожидание subprocess и inference
могут пересекаться, а workload и частота событий отличаются. Пробу с моделями
после этого изменения не выполняли.
