После успеха или ошибки выполняется очистка собственного контура с независимой проверкой процессов/групп/БД/socket/секретов; приватные свидетельства сохраняются.

## Что проверяем

При успешной обработке проверяем накопление0→5→10 и сохранение первых members, SQL-checkpoint, vector values и checkpoint-файлов, как в исходном предложении. Если resource sensor снова даст STOP, проверяем сохранённый диагностический код проверки, тип исключения и актуальность sample. Повтор не гарантирует воспроизведение прежней причины: состояния машины и timing различаются. Успешный повтор также не устанавливает точную причину прошлого STOP.

При ошибке записи самого resource журнала причина может не сохраниться в этом же файле; это ограничение описано в диагностике. Конкретная причина прошлого measurement failure остаётся UNKNOWN, отдельный component RSS ceiling не исключён. Пределы ради прохождения теста не повышаются.

Оба package SHA,81codefiles, hashes/input bytes/DTO/permissions проверены; десять input SHA различны между партиями, shared target/checkpoint/runtime согласован. Полный code inventory сравнен с предыдущей серией: отличается только указанный диагностический адаптер.

Две metadata-only сборки I прошли без SDK/сервера; шесть реальных interpreter entrypoints отказали proposed control с code5, inventories совпали. Native перед загрузкой проверяет encoder weights; повторный полный rehash на подготовке не выполнялся. Синтаксис runner и сохранение трёх прежних исправлений проверены; полного исполнения обновлённого runner не было.

Последние119релевантных тестов новой диагностики прошли в предыдущей задаче; после неё продуктовый код не менялся, suite повторно не запускался. Независимое review не проводилось. Синтетические тесты не заменяют реальное подтверждение нового diagnostic поля во время ML.

## Допуск

Нужно разрешение ровно этих двух пакетов на два последовательных START в одном собственном временном контуре и итоговую очистку. RESUME, crash injection, постоянный сервис, третья партия, установка зависимостей, увеличение лимитов, рабочая активация и commit/push/merge не входят в допуск.
