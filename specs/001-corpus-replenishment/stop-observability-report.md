# Диагностика остановки: первая причина и итоговая сводка

2026-10-15. STANDARD. Реализовано по подтверждённому владельцем предложению:
код и немодельные проверки, затем подготовка отдельной ML-пробы.
Новых правил обработки, ресурсных лимитов и разрешений на runtime нет.

## Что изменилось

`MacResourceObserver` сохраняет время последнего достоверного полного измерения.
Превышение RSS отдельной worker-группы обозначается `RSS_LIMIT` с проверкой
`WORKER_RSS`; некорректная настройка лимита остаётся ошибкой измерения.
Общие исходы `OK/WARNING/STOP` и защитное поведение прежние.

`RecordingResourceObserver` один раз сохраняет `resource-stop.json` рядом с
`resource-observations.jsonl`. Первая причина фиксируется до записи контекста
и основного журнала; последующие ошибки записи её не заменяют. Файл содержит
причину, проверку, доступный полный sample, его исходное время и признак
актуальности на момент STOP. Ошибка самого observer отличается от ошибки журнала.
Приватный каталог700, файл600, атомарная замена и fsync файла/каталога;
дополнительный файл не больше4096bytes на execution root, без ротации.

Если сам диск/каталог недоступен, отдельный файл тоже может не сохраниться:
STOP остаётся обязательным, отсутствие свидетельства означает UNKNOWN.
Сохранение файла не гарантируется при SIGKILL до его записи. Новый процесс
не восстанавливает причину смерти controller по догадке.

Терминальный монитор читает первую причину, место проверки, состояние последнего
worker (код выхода/сигнал/запрошенная остановка), время и полноту доступной истории.
Причины показаны по-русски вместе с кодами. `SIGKILL` не объявляется OOM.
Неполная строка журнала помечает историю неполной. Повторный STOP/свежий heartbeat
не обновляет возраст прежнего измерения. Для старых журналов время sample и
неизвестная причина остаются UNKNOWN.

`--json` возвращает ту же сводку в stdout, включая `failure`: причина, проверка,
измерения и их возраст, worker exit, стадия/модель, длительность и состояние
закрытия controller. Viewer по-прежнему только читает файлы; отчёт на диск
самостоятельно не записывает. Состояния и checkpoints остаются в БД.

Экспериментальный `candidate_i_probe_watchdog` сохраняет разрешённый первичный
код из trace вместо безусловного `RESOURCE_OBSERVATION_ERROR`, безопасные
RSS/MPS/pressure/swapouts из STOP-события и отдельное действие
`SIGKILL_OWNED_GROUP`. Это запись отправленного сигнала, не диагноз причины
гибели. Незнакомый код скрывается как `RESOURCE_OBSERVATION_ERROR`.

## Проверка

TDD RED→GREEN: отсутствующая первая причина; ошибка записи основного stream;
ошибка observer; сохранение причины при последующей ошибке context; отдельный
worker RSS ceiling; ложная свежесть latched STOP; неполная строка; JSON-вывод;
передача точного кода и MPS в watchdog. Семь вариантов watchdog выполняют
настоящий SIGKILL только собственному синтетическому subprocess. Модели и БД
в этих проверках не используются. Проверки подтверждают защитное поведение
и состав evidence; историческую причину STOP они не устанавливают.
