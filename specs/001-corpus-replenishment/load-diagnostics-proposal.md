## Что добавлено

Диагностика включается явным load_diagnostics=true в замороженном runtime binding.
По умолчанию она выключена. Наблюдение остаётся в инфраструктуре; правила
пополнения, пороги, параметры моделей, входные фото и алгоритмы не менялись.

| Точка измерения | Что сохраняется |
|---|---|
| Загрузка Grounding DINO / SAM2 | Границы загрузки; живая память тензоров и память MPS driver |
| Вызов Grounding DINO / SAM2 | Границы вызова, накопленное CPU-время, RSS, MPS |
| Фото и проход локализации | Числовые номера вызовов; первый и возможный второй ROI-проход различимы по вложенным событиям |
| Загрузка encoder / обработка фото | Границы вызова; модель определяется приватным control файла стадии |
| Допуск по ресурсам / checkpoint | Начало, завершение или ошибка операции; связь с ожиданием |
| Собственные процессы, в том числе во время ожидания | RSS и CPU-время controller, ML worker и owned child (guardian в текущем составе) |
| Машина | pressure, свободные/неактивные страницы, pageouts, используемый swap |
| Временная PostgreSQL | Память только собственного контейнера, отдельно от RSS macOS |

Каждая запись содержит wall-clock и monotonic, а также длительность снятия метрик.
Точки внутри модели не сохраняют аргументы, изображения, маски, SQL, пути,
идентификаторы товаров или сообщения исключений. Порядок вызовов позволяет
связать фото, проходы и операции без исходных идентификаторов.

Обёртки передают исходные аргументы и сохраняют исходные результаты/исключения.
Они не вызывают empty_cache, reset_predictor, сборку мусора или MPS synchronize.
Поэтому эта проба проверяет существующий алгоритм, без попытки снизить нагрузку.
Результаты тестов не заменяют проверку реального SDK при следующем запуске.

## Ограничения измерений

- driver_allocated_memory включает кеш allocator и выделения MPS/MPSGraph;
  current_allocated_memory измеряет живые тензоры. Разница не является точным размером кеша.
- CPU-время накопленное, не загрузка CPU в процентах. GPU utilization в процентах не измеряется.
- Границы вызовов отражают время Python-вызова; без MPS synchronize это не чистое время GPU.
- Дополнительное чтение OS-метрик и fsync добавляет накладные расходы.
  sample_seconds позволяет видеть часть этих расходов; сравнение со старой длительностью
  не доказывает изменение производительности алгоритма.
- Parent-сэмплы идут не чаще раза в секунду; Docker memory проверяется не чаще раза
  в пять секунд, возраст кешированного измерения сохраняется. Краткие пики могут быть пропущены.
- Память контейнера Docker не равна RSS процесса macOS и не включает полный footprint Colima VM.
- Каждому диагностическому JSONL отведено до 1 MiB, записи — до 4096 байт,
  файлы 600 в приватном каталоге 700. Итоговый status.json отдельно содержит
  incomplete и bytes_written. Отсутствие status после аварийного завершения — UNKNOWN.
- Ошибка измерения или исчерпание лимита делает диагностику неполной; она не заменяет
  исходную ошибку и не ослабляет существующую ресурсную защиту.

Проверены actual host wiring с включённой/выключенной диагностикой и native I
wiring с fake SDK/socket. Это не полный test suite и не реальная модельная проба.
Ruff и git diff --check проходят. OS-сборщик на macOS прочитал CPU/RSS/pressure/
swap/pageouts; модельные SDK не импортировались.

I metadata/inventory/VCS/runtime/config и metadata-only assembly проверены заново.
Три actual environment entrypoints отказали без допуска, code5, без ML SDK imports.
Полный rehash 87 encoder files в этой подготовке не повторялся; ранее проверенные
веса сохранены, native stage проверяет их перед загрузкой.

Ошибки команд сохранены отдельно от TDD: первый pytest запуск без PYTHONPATH,
отсутствовавший pytest import в изменённом тесте, затем шесть socket setup failures.
Последние вызваны длинным временным путём macOS (122 байта, AF_UNIX path too long),
а не дефектом диагностики. Проверки прошли с новым коротким basetemp в /private/tmp.
