Добавлены восемь случаев в `tests/test_replenishment_acceptance_flow.py`:

- Семь фото: первый явно разрешённый запуск обрабатывает пять и не публикует;
  второй явно разрешённый запуск обрабатывает оставшиеся два, сохраняет редакцию
  и публикует все семь. Checkpoints20→28, vectors21, publication1.
- Сводка отличает WAITING_PHOTOS, NOT_PUBLISHABLE и PUBLICATION_FAILED;
  показывает оставшиеся фото полной редакции, а не только текущей партии.
- Изменение входа или профиля создаёт новую редакцию. Старый снимок сохраняется;
  несовместимый профиль получает PROFILE_MISMATCH до переключения active pointer.
- Ошибки одного товара не мешают публикации другого готового товара.
- Downgrade0010→0009 и последующий upgrade проходят во временной БД с данными;
  product_records сохраняются, новые progress/catalog таблицы после upgrade пусты.
- CLI принимает разрешённые поля сводки и отклоняет лишнее поле с raw path.
  Два варианта этого сценария считаются двумя параметризованными случаями.

Прежние native-сценарии включают exec/FD inheritance, смерть родителя с живым
дочерним процессом, отказ второго владельца, TERM/KILL только собственных групп,
сохранение lease при неподтверждённом teardown и racing SEARCH→DRAINING→BUILD.
Их результат учитывается в общей регрессии, без отдельного повторного счёта.

полю `products`: из старой сводки нельзя было узнать об оставшихся двух фото либо
отличить товар без готовых фото. После добавления read projection в repository
и строгой проверки полей CLI — 4 passed. Изменение относится к исполнению уже
принятых FR-067/068, а не к новому требованию.

Расширенная выборка сначала дала 1 failed / 7 passed. Тест смены профиля неверно
ожидал ERROR публикации: существующий `resolve_active` раньше отказывает с
PROFILE_MISMATCH. После сверки модели совместимости ожидание исправлено на REFUSED;
проверки новой current revision/профиля и сохранения старого snapshot оставлены.
Продуктовый код ради этого теста не менялся. Это ошибка ожидания, не новый RED
отсутствующей функциональности. Итог новых сценариев: 8 passed.

Для rollback расширен только test helper: `migrate(direction=upgrade/downgrade)`;
неизвестное направление отклоняется, DB identity, очищенное окружение и сроки
сохранены. Downgrade выполнялся исключительно в новом синтетическом контейнере.
