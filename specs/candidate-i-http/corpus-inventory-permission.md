## Основание и маршрут

Подготовка — STANDARD: подготовить ограниченный пакет без чтения restricted-данных → сверить
границы с [T050–T055](tasks.md) и [принятым runtime](runtime-profile-reference.md) →
проверить ссылки и структуру → предъявить владельцу. Независимое review не требуется
по умолчанию; нормативное принятие и выполнение inventory не входят в подготовку.

Проверка границ последующего разрешения — FULL: записать разрешение владельца только
на runtime/availability → проверить metadata identity и фактическую доступность контура → один
независимый read-only review → передать конкретное препятствие владельцу.
Новые data/model/build/activation действия за пределами T050 не разрешаются.

## Предлагаемые операции

| Объект | Что проверить | Что сохранить |
|---|---|---|
| Identity корпуса | Сопоставить выбранную версию с ранее принятым источником; установить текущий состав | Безопасное подтверждение identity и агрегаты; точные IDs только приватно |
| Связь товара и фото | Проверить весь перечень выбранной версии: отсутствие потерянных ссылок и неоднозначной принадлежности | Числа товаров, ссылок, отсутствующих и неоднозначных связей |
| Локальные фото | Существование, читаемость, размер; SHA-256 потоковым чтением каждого разрешённого файла | Агрегаты доступности и объёма; per-file manifest только приватно |
| Freeze входов | Зафиксировать состав и hashes, порядок и привязку к товарам для будущего build | Приватный manifest; безопасный итог в `build-readiness.md` |

Для принадлежности достаточно ссылочной связи из авторитетного каталога. Inventory
не устанавливает, что изображение визуально соответствует товару, не оценивает ногти
и не доказывает качество поиска. Неоднозначность фиксируется как пробел.

Предлагаемый объём — одна выбранная версия корпуса, все её записи и связанные
локальные фото, один проход без автоматических повторов. Не обходить соседние
каталоги, Candidate J или другие версии. При выходе локатора за подтверждённый корень,
неизвестной identity либо неожиданном составе остановиться до уточнения владельца.

Если авторитетная связь доступна только в БД, в разрешение нужно включить именно
существующий контур Gate 2: проверка его identity, read-only transaction и точечные
SELECT по выбранной версии. Кроме отдельно согласованного ниже exact Gate 2 start
не запускать контейнеры, не читать другую рабочую БД,
не применять миграции и не выгружать полные таблицы. Если достаточно существующего
приватного manifest с подтверждённой provenance, доступ к БД не нужен.

## Конкретное разрешение, принятое последним «да»

Запустить только существующий остановленный `ai_gate2_one_time-database-1` через
`docker --context colima start ai_gate2_one_time-database-1`, без Compose up,
recreate, pull, migration, удаления volumes или запуска других контейнеров. Это запуск
PostgreSQL, а не read-only операция: при старте возможны штатные записи/восстановление
в существующем DB volume. Затем проверить readiness и identity; если они подтверждены,
выполнить описанный в пакете однократный read-only T050 с transaction READ ONLY,
потоковым хешированием связанных фото и отдельным приватным manifest, безопасный
итог сохранить в `build-readiness.md`.
При несовпадении identity остановиться, не подставлять другую БД. Запуск этой БД
и inventory были отдельно разрешены последним owner «да»; выполнены согласно
[T050 report](build-readiness.md). ML/build/activation не выполнялись.
