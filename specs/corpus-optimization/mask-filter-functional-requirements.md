## 1. Назначение и границы

Документ описывает наблюдаемое поведение системы при отборе масок одного фото
для дальнейшей обработки по отдельным ногтям. Один сценарий применяется к фото
поискового запроса и к фото каталога с соответствующим выбранным профилем.

Включены: получение кандидатов, применение политики отбора, объяснение решений,
формирование результата и реакции на неразрешённые случаи/ошибки.

Не включены: новый UI или endpoint, ручная разметка как функция продукта,
выбор модели/порогов, исправление и создание масок, увеличение лимитов,
изменение matching/формул, автоматическая пересборка либо активация каталога.

Подробные предметные определения и ограничения сохраняются в
[кандидатах правил](mask-filter-rule-candidates.md), архитектура — во
[вводных HLD](mask-filter-hld-inputs.md). Параметры качества/производительности,
схема данных и критерии приёмки не определяются этим документом.

## 2. Акторы и используемые понятия

| Актор / понятие | Роль в сценарии |
|---|---|
| Пользователь CHECK | Инициирует поиск с фотографией в существующем сценарии UC-001 |
| Владелец проекта | Инициирует разрешённую обработку каталожных фото в существующем сценарии UC-007 |
| Кандидат | Маска одного исходного изображения, полученная до отбора; краткое пояснение из [словаря](mask-filter-rule-candidates.md#понятия-которые-нельзя-смешивать) |
| Политика отбора | Применимые правила и параметры; содержание пока обсуждается отдельно |
| KEEP / REJECT / UNCERTAIN | Предлагаемые результаты оценки отдельного кандидата: положительное решение, исключение, неразрешённость; не значения photo-level HTTP статуса |

Новый пользовательский актор или право доступа не вводятся. Сценарий ниже —
вложенная системная часть существующей обработки фото, не новая кнопка продукта.

## 3. UC-011 — Отобрать маски одного фото

**Акторы:** CHECK при поиске; владелец проекта при обработке каталога.
**Цель:** получить результат отбора с объяснимыми решениями и явно отмеченными
неразрешёнными случаями для дальнейшей обработки фото.

**Триггер:** завершено получение набора масок-кандидатов для выбранного фото.
Пустой набор является допустимым случаем входа, но имеет отдельный поток.

**Предусловия:** определены исходное фото, контекст его обработки и применимая
версия профиля; доступна политика отбора, выбранная для этого профиля.
Утверждение политики и критериев — зависимость будущего запуска, сейчас не закрыта.

**Основной поток — корректный непустой вход с разрешёнными решениями:**

1. Система принимает набор кандидатов одного фото и применимый профиль.
2. Проверяет пригодность входа к оценке и его связь с выбранным фото/профилем.
3. Рассматривает кандидатов совместно и применяет правила отбора.
4. Для каждого кандидата формирует одно решение и его основание.
5. Формирует набор положительно выбранных масок, сохраняя связь с исходными кандидатами.
6. Проверяет, не превышено ли допустимое число положительно выбранных областей.
7. Возвращает результат отбора и сведения о применённой версии политики.

**Постусловия основного потока:** для каждого исходного кандидата есть одно
решение; положительно выбранные маски не изменены геометрически; исключённые
маски не входят в положительный набор; результат связан с исходным фото и
применённой политикой. Готовность товара/публикация не являются постусловиями.

### Альтернативы и ошибки

| Ситуация | Реакция в границе черновика | Открытая зависимость |
|---|---|---|
| Локализатор вернул пустой набор | Сообщить, что кандидаты отсутствовали на входе; не выдавать это за результат их исключения фильтром | Согласовать отображение в существующие исходы фото |
| Все решения — REJECT | Сообщить, что все кандидаты исключены оценкой, с основаниями | Не приравнивать автоматически к NO_NAILS; конечный исход фото не выбран |
| По доступным входным сведениям известно, что после исключения составной маски часть представленных в ней ногтей не имеет отдельных пригодных масок, но другие KEEP остаются | Решения по кандидатам сохраняются; наличие KEEP само по себе не подтверждает полноту и готовность всего фото | Итог фото при известном частичном покрытии не выбран; обнаружение неизвестных пропусков не добавляется |
| Есть UNCERTAIN, с KEEP или без KEEP | Отразить спорные кандидаты отдельно от положительно выбранных и исключённых | Передача спорных областей дальше и конечный исход фото не выбраны |
| Невалидный вход или несоответствие фото/профиля | Сообщить причину невозможности оценки; не создавать фиктивные предметные решения | Точные внешние коды — последующий контракт |
| Не выполнена необходимая внешняя оценка | Сообщить технический неуспех этой оценки отдельно от решений о содержимом | Завершение всего фото/допустимая деградация ещё не выбраны |
| Положительных масок больше допустимого | Сообщить превышение; не удалять положительные маски для попадания в лимит | Сам лимит здесь не изменяется |
| Маска ногтя включает кожу или кольцо | Решение зависит от ещё не выбранного критерия пригодности | Ответ владельца на предыдущий вопрос не поступил |
| Нельзя обоснованно выбрать пригодное представление среди возможных дублей | Не исключать кандидата только по неподтверждённой гипотезе дубля; отразить неразрешённость | Критерий эквивалентности и выбора сохраняемой маски открыт |

Альтернативы описывают результат отбора, а не новый набор публичных статусов.
Автоматическое продолжение embeddings/publication при любой из этих альтернатив
настоящим документом не разрешено.

## 4. Функциональные требования

Канонические формулировки новых UC/FR находятся только здесь. Основания ниже
ссылаются на обсуждаемые правила; соответствующие FR остаются зависимыми от
их уточнения и утверждения. Слова «подтверждённый» и «пригодный» не являются
готовым алгоритмом определения истинности.

### Вход и оценка кандидатов

| ID | Формулировка | Основание / зависимость |
|---|---|---|
| FR-072 | Система должна принимать для отбора набор кандидатов одного исходного фото вместе с контекстом применимого профиля обработки. | UC-011; [границы pre-HLD](mask-filter-hld-inputs.md#данные-на-границе) |
| FR-073 | Если вход не позволяет выполнить оценку для указанного фото и профиля, система должна сообщать причину отказа в оценке. | UC-011, альтернатива невалидного входа; [технический отказ](mask-filter-rule-candidates.md#ограничения-и-предохранители) |
| FR-074 | Система должна формировать положительное решение для пригодных масок отдельных ногтей по применимой политике отбора. | [Сохранение отдельного ногтя](mask-filter-rule-candidates.md#кандидаты-правил-по-маскам); критерий пригодности открыт |
| FR-075 | Система должна разрешать подтверждённые дубли кандидатов совместно, выбирая сохраняемое пригодное представление по применимой политике. | [Удаление дубля](mask-filter-rule-candidates.md#кандидаты-правил-по-маскам); эквивалентность и выбор представителя открыты |
| FR-076 | Система должна формировать решение об исключении подтверждённых составных масок по применимой политике. | [Исключение группы](mask-filter-rule-candidates.md#кандидаты-правил-по-маскам); способ подтверждения группы открыт |
| FR-077 | Система должна формировать решение об исключении подтверждённых посторонних масок по применимой политике. | [Исключение постороннего объекта](mask-filter-rule-candidates.md#кандидаты-правил-по-маскам); критерий содержимого открыт |
| FR-078 | Система должна сохранять положительные решения для пригодных масок разных ногтей при пересечении их областей или ограничивающих прямоугольников. | [Сохранение различимых соседних ногтей](mask-filter-rule-candidates.md#кандидаты-правил-по-маскам); пригодность и различимость требуют определения |
| FR-079 | Если доступные свидетельства не позволяют принять положительное решение или решение об исключении, система должна формировать UNCERTAIN для соответствующего кандидата. | [Сохранение неопределённости](mask-filter-rule-candidates.md#кандидаты-правил-по-маскам); не задаёт downstream-поведение |

### Результат и объяснение

| ID | Формулировка | Основание / зависимость |
|---|---|---|
| FR-080 | Для каждого кандидата корректно оценённого входного набора система должна возвращать ровно одно решение, связанное с этим исходным кандидатом. | UC-011; [смысл решений](mask-filter-rule-candidates.md#кандидаты-правил-по-маскам) |
| FR-081 | Система должна возвращать основание каждого решения об отдельной маске. | [Объяснение решения](mask-filter-rule-candidates.md#ограничения-и-предохранители); не требует нового UI или постоянного хранилища |
| FR-082 | Система должна представлять положительно выбранные, исключённые и спорные кандидаты как различимые части результата отбора. | UC-011; [маска и итог фото](mask-filter-rule-candidates.md#маска-и-итог-фото--разные-решения); не предписывает embeddings для UNCERTAIN |
| FR-083 | Система должна возвращать выбранные исходные маски без изменения их геометрии в рамках операции отбора. | [Отбор без исправления](mask-filter-rule-candidates.md#ограничения-и-предохранители); предложенная граница первой итерации |
| FR-084 | При исключении кандидата как дубля система должна указывать сохраняемый кандидат с положительным решением, представляющий тот же ноготь. | [Удаление дубля](mask-filter-rule-candidates.md#кандидаты-правил-по-маскам); правило подтверждения того же ногтя открыто |

### Альтернативные исходы и профиль

| ID | Формулировка | Основание / зависимость |
|---|---|---|
| FR-085 | При отсутствии положительно выбранных масок система должна сообщать причину такого результата, различая отсутствие кандидатов на входе, исключение всех кандидатов и наличие неразрешённых оценок. | Альтернативы UC-011; не переопределяет NO_NAILS и не вводит публичный enum |
| FR-086 | При техническом неуспехе необходимой оценки система должна сообщать о нём отдельно от решений о содержимом масок. | [Отделение технического отказа](mask-filter-rule-candidates.md#ограничения-и-предохранители); стратегия завершения/деградации открыта |
| FR-087 | При превышении допустимого числа положительно выбранных областей система должна сообщать превышение без удаления положительно выбранных масок ради соблюдения лимита. | [Не подгонять под10](mask-filter-rule-candidates.md#ограничения-и-предохранители); значение лимита задаётся вне этого документа |
| FR-088 | Система должна связывать возвращаемый результат отбора с применённой версией политики и её параметров. | [Профиль и совместимость](mask-filter-hld-inputs.md#что-меняется-и-что-может-сохраниться); формат и хранение ссылки не заданы |
| FR-089 | При обработке фото запроса и каталожных фото система должна применять политику отбора, соответствующую выбранному представлению для сравнения. | Общая граница UC-011; [query/catalog consistency](mask-filter-hld-inputs.md#проверки-которые-следует-заложить-в-hld); правило совместимости версий требует уточнения |

FR-080 относится к завершённой предметной оценке. Технический отказ по FR-073/
FR-086 не должен фабриковать решения для кандидатов, которые не были оценены.
FR-085 различает причины отсутствия положительных масок; сочетание REJECT и
UNCERTAIN должно оставаться видимым по FR-082, а не теряться в единственной метке.

Наличие KEEP также не подтверждает полного покрытия ногтей фото: известный
случай отсутствующих отдельных масок после исключения группы оставлен отдельной
альтернативой UC-011. Новый поиск неизвестных пропущенных ногтей не требуется.

## 5. Связь с существующими требованиями

Новые формулировки не заменяют утверждённые требования
[пополнения корпуса](functional-requirements.md):

| Существующее требование | Граница изменения |
|---|---|
| FR-020 — выбранные фото и согласованный профиль | Новый отбор является частью выбранного профиля, не разрешает менять его во время работы |
| FR-027 — создание crops по областям и маскам | Новые требования описывают предшествующий отбор; создание crops здесь повторно не специфицируется |
| FR-032 / FR-034 / FR-035 — пригодность результатов, переиспользование и смена профиля | Нужна увязка версии отбора с представлением; автоматическая пересборка не назначается |
| FR-036 — локализатор не нашёл ногти | Не расширяется на случай, когда фильтр исключил все маски |
| FR-037 — ошибка фото | Предметная неразрешённость маски не объявлена технической ошибкой автоматически |
| UC-001 / UC-007 — поиск и обработка каталога | UC-011 раскрывает общую вложенную функцию; не создаёт новое право запуска или публикации |

## 6. Открытые решения, ограничивающие полноту

| Вопрос | Затронутые функции | Что не решено |
|---|---|---|
| Что считать пригодной маской, в том числе ноготь с кожей/кольцом и неполной границей? | FR-074–FR-079, FR-084 | Критерий полезности, предел постороннего содержимого и полнота |
| Как подтверждать дубль/группу/посторонний объект и выбирать пригодного представителя? | FR-075–FR-077, FR-084 | Предметные критерии и необходимые свидетельства; алгоритм и пороги — отдельный дизайн |
| Что делать с UNCERTAIN в реальной обработке? | FR-079, FR-082, FR-085 | Передавать дальше, останавливать фото либо направлять на разбор; выбор не сделан |
| Как завершать фото без положительных масок? | FR-085 | Значение конечного исхода и связь с NO_NAILS |
| Как завершать фото при известном неполном покрытии, если некоторые KEEP остаются? | FR-076 / FR-082, альтернатива UC-011 | Исход фото и влияние известного отсутствия отдельных пригодных масок после исключения группы; автоматически находить все неизвестные пропуски не требуется |
| Как обрабатывать недоступность необходимой внешней оценки? | FR-086 | Завершение фото или явно допустимая деградация |
| Как связывать профиль отбора с представлением и разрешать совместимость версий? | FR-088 / FR-089 | Смысл совместимости, миграция и объём переобработки |

Бизнес-правила и соответствующий целевой процесс фильтра остаются неутверждёнными
входами ART-05/ART-04. Поручение SRC-094 позволяет собрать этот черновик, но не
закрывает upstream owner gates. До их закрытия и решений таблицы документ нельзя
представлять как полный утверждённый контракт реализации.

## 7. Подготовка и проверка

Короткий план-контракт, FULL: сверить ART-06 и существующие IDs → сформировать
отдельный DRAFT по возможности и источник поручения → добавить в индекс ART-06
без изменения утверждённых UC/FR → самопроверка границ/ссылок/IDs/таблиц → один
независимый read-only reviewer → исправления; повтор review обязателен после
Critical/Major → предъявить владельцу с открытыми решениями. Изменения кода,
реализация, API/OpenAPI и запуск моделей не входят в задачу.

Источники проверены в текущем checkout; SRC-094 фиксирует только поручение
подготовки. FR-072–FR-089 и UC-011 выделены после проверки существующего набора.
Подробные правила не продублированы в ART-06; архитектура и варианты остаются
во вводных HLD, данные/NFR/критерии приёмки этим текстом не задаются.

Самопроверка:18 уникальных FR и1 UC; релевантные ссылки/anchors, границы,
источники и статусы проверены.

Независимое read-only review — PASS для DRAFT:0 Critical/0 Major/1 Minor.
Minor касался известного частичного покрытия при наличии других KEEP;
альтернатива UC-011 и открытый вопрос дополнены, самопроверка повторена.
Второе review не проводилось: по AGENTS после единственного Minor достаточно
исправления и самопроверки. Проверка документа не закрывает открытые решения.

Утверждение владельца: отсутствует.
