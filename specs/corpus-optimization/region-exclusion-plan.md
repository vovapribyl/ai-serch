# Диагностическое исключение областей: план offline-сравнения

2026-10-15. STANDARD. **EXECUTED / OK**. [Результат](region-exclusion-report.md). Владелец ответил «Разрешаю» на предложение
сравнить ранги с исключением кольца и дублей на сохранённых векторах, без ML.
Основания: [визуальный разбор](localization-review.md) и
[семь завершённых запросов](remaining-quality-report.md).

До расчёта фиксируются следующие варианты:

| Вариант | Изменение относительно исходных данных |
|---|---|
| Исходный | Все области сохранены |
| Только кольцо | У запроса 6 исключается область 6; остальные запросы и каталог прежние |
| Только дубль | У ожидаемого фото запроса 5 исключается область 3; остаются 1 и 2 |
| Только украшение | У того же фото исключается область 2; остаются 1 и 3 |
| Дубль и украшение | У того же фото остаётся область 1 |
| Кольцо + дубль и украшение | Совмещаются два указанных изменения |
| Проверка выбора оставшейся маски | Вместо области 1 у того же фото остаётся область 3; кольцо сохраняется |

Маска 1 выбрана заранее: при визуальном просмотре она полнее и чище представляет
ноготь, чем маска 3. Последний вариант проверяет чувствительность к этому выбору;
он не используется для подбора лучшего результата. Остальные фото, в том числе
малые неоднозначные области 9–10 запроса 7, не меняются.

Для каждого варианта рассчитываются все семь комбинаций моделей и все семь
запросов к прежним 20 фото. Сравниваются ранг правильного товара, его score,
score лидера и top-5 на трёх положительных запросах двух товаров.
Для четырёх отсутствующих запросов сохраняются scores/margins; без порога
отказа они не засчитываются как true negatives.

Сначала исходный вариант должен в точности воспроизвести все прежние scoring
details. Контрольные суммы exports, code и models/semantic/extractor identity
проверяются до расчёта. После исключения области ordinals перенумеровываются
только в диагностическом DTO; исходный номер и выбор сохраняются в manifest.
Оставшиеся векторы берутся без изменений. Core parity проверяется для всех
трёхмодельных query/catalog пар каждого варианта. Общий deadline — 600 с.

Это изменение данных внутри отдельного эксперимента, а не новый фильтр
продукта. Очистка только известного ожидаемого фото — адресная диагностика,
не unbiased-оценка системы на новом каталоге. Пропущенные ногти не восстанавливаются.
Более низкий ранг после удаления дублей не делает эти дубли правильными.

Продуктовый код, исходные exports/изображения/labels, формула, набор моделей
и лимиты не меняются. ML/БД/установка/cutover/50–100/commit/push не выполняются.
Приватные детали сохраняются в ignored artifacts. Независимое review
не проводилось; итог будет определён фактическим сравнением, без подбора новых
вариантов по получившимся рангам.
