Владелец передал семь PNG для четырёх товаров. Номер строки в имени задаёт
ожидаемый товар, суффикс обозначает разные фотографии одного товара.
Это разметка владельца; номер строки не подменяется порядковым номером в subset.

Read-only проверка source_row в частных metadata сохранённого manual20:
два товара отсутствуют (четыре запроса), два присутствуют (три запроса).
SHA-256 selection совпал с [отчётом manual20](../candidate-i-http/manual-quality20-report.md).
Проверка относится к этому сохранённому subset, а не к текущей рабочей БД.

Семь файлов доступны. Частный manifest сохраняет SHA-256/размер каждого PNG,
сопоставление с товаром, membership и контрольные суммы metadata/selection.
Фото, реальные строки, идентификаторы и исходные пути в Git не копировались.

Для трёх запросов с присутствующим товаром можно оценить ранг и top-k.
Четыре запроса отсутствующих товаров рассматриваются отдельно: top-k сам по себе
не доказывает корректное распознавание отсутствия; нужен явный критерий отказа.
Семь фото не являются семью независимыми товарами. Сходство конкретного запроса
с исходным фото каталога и возможные дубликаты ещё не проверены.
