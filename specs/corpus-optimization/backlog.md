## Ближайшее: пропуск фото с превышением лимита

**Статус: дизайн утверждён владельцем «Хорошо, приступай»; код реализован
и проверен на синтетических данных. Новый ML-пакет не подготовлен/не запускался.**

Временно не включать в корпус фото, для которых локализатор вернул
`REGION_COUNT_LIMIT` (текущий предел10), но сохранять возможность найти и
переобработать исходник позже. Не удалять фото и не усекать маски до top10.

Согласованный поток:

1. Получить ответ локализатора. При REGION_COUNT_LIMIT сохранить фото
   как неуспешно обработанное; embeddings для него не считать.
2. До проверки итогов партии и удаления тестового SQL-контура атомарно
   сохранить приватный список отложенных фото. Он содержит связь с товаром,
   устойчивый идентификатор/ссылку исходного фото, input SHA, причину
   REGION_COUNT_LIMIT и ссылку на операцию. Индекс внутри временной партии
   или обезличенный идентификатор журнала не заменяет исходный идентификатор.
3. Продолжить следующие фото/партии, сохранив результаты готовых.
4. В отчёте разделить готовые, отложенные по лимиту и остальные ошибки.
   План100 входов не объявлять100 готовыми, если часть пропущена.
5. Повторять отложенные фото только отдельным будущим пакетом;
   автоматических повторов не делать.

Граница обхода — только REGION_COUNT_LIMIT. Остальные ошибки
не считать разрешёнными пропусками автоматически; ресурсные STOP, ошибки
очистки и невозможность сохранить список останавливают кампанию.

Текущее ядро `corpus_replenishment.py` уже продолжает обработку после
PhotoProcessingError, сохраняя исход ERROR, но не его точный код в этом
обработчике. Внешний проверяющий runner ранее требовал все фото OK и
остановил серию. Поэтому нужны адресные изменения runner/экспорта, а не
переписывание локализатора. Существующие ERROR/NO_NAILS не переклассифицировать
без исходной причины. Список ошибок не является очередью автоматического
исполнения и не меняет готовность товара по утверждённым требованиям.

Проверка до ML: синтетическая партия с успешным фото, REGION_COUNT_LIMIT
и следующим успешным фото; сохранение исходных идентификаторов, продолжение,
экспорт до cleanup, отказ при ошибке записи и сохранение защитного STOP.
Новый реальный прогон требует отдельного конечного пакета и разрешения.

Все исходные идентификаторы, файлы и списки остаются в приватных runtime
артефактах вне Git. В этом бэклоге — только описание задачи.


### Реализация и доступ к списку

В native host добавлен opt-in `defer_region_limit: true` в закреплённом
runtime-binding. Для этого режима обязательны hash полного input inventory
`deferred_inventory_sha256` (SHA-256 canonical JSON) и pin исходника
`src/product_search/infrastructure/replenishment_deferred_photos.py` в code inventory.
Отсутствующий/ложный hash или неточный тип флага дают отказ до создания runtime.
Это защищает также mapping исходных ID, который не входит в прежний hash
одних выбранных продуктов. Старые пакеты и их замороженные runner не менялись.

`DeferredPhotos` создаёт `deferred-photos.json` в private_root нового host;
папка700, файл600. Новые партии того же host дополняют один список. Повторный
host не перезаписывает прежний файл; повторная обработка требует нового пакета.
Запись атомарна, файл и каталог fsync; потолок2MiB, без ротации с потерей строк.
Превышение потолка/ошибка IO останавливают кампанию. Список сохраняется перед
фиксацией ERROR в БД. Другие photo errors в этом opt-in режиме также останавливают
кампанию; исходный default-путь без флага не меняется.

Для новых внешних runner вместо проверки «все OK» предусмотрен
`export_deferred_batch`: сначала partial export, затем проверка, что все ERROR
связаны с сохранённым REGION_COUNT_LIMIT и правильным SHA. PENDING/неучтённый
ERROR/неверный SHA не проходят. Это не заменяет проверки guards/cleanup,
checkpoint/vector completeness и сохранности прежнего каталога в будущем пакете.
Исторические одноразовые runner остались неизменными и не переиспользуются.

Просмотр итогов в терминале из корня проекта:

```bash
.venv/bin/python scripts/report_replenishment_batch.py \
  --catalog artifacts/corpus-replenishment/<папка-прогона>/quality-catalog-vectors.json \
  --deferred artifacts/corpus-replenishment/<папка-прогона>/deferred-photos.json
```

Заменить `<папка-прогона>` на фактический каталог; это шаблон, не готовая команда.
Команда только читает файлы, выводит ready/deferred/no_nails/other_errors/pending/total
и абсолютный путь списка; сырые ID в сводку не выводятся. Ошибка проверки —
ненулевой exit code. В исходном JSON доступны исходные идентификаторы.
При архивировании новой партии список нужно переносить вместе с остальными
private evidence до удаления её временного каталога/SQL-контура.
