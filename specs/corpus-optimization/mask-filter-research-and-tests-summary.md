# Отбор масок: итоги исследования и диагностических тестов

2026-10-19. STANDARD. **Сводка evidence и предложений для HLD**.
Документ объединяет существующие результаты; не утверждает новые правила,
пороги, требования, архитектуру или качество автоматического фильтра.
Новых вычислений моделей и контрольных прогонов для этой сводки нет.

## Основной вывод

Потребность в отборе масок подтверждается конкретными посторонними объектами,
дублями и составными выделениями. Адресная очистка улучшила один пример поиска.
Однако достаточность фильтра для хорошего поиска не подтверждена:
пропуски ногтей, неточная геометрия, различение похожих дизайнов и зависимость
score от числа областей — отдельные проблемы.

Автоматический фильтр на независимом наборе ещё не оценён. Выполненные опыты
проверяли последствия ручного выбора масок и их исправления, а не способность
алгоритма самостоятельно принять правильные решения.

## Что дало исследование

[Обзор первичных источников от18 октября](mask-filtering-research.md) даёт следующие
основания для проектирования; конкретные пороги из него не следуют:

- Confidence распознавания объекта и качество его маски различаются.
  Высокая уверенность не доказывает выделение одного отдельного ногтя.
- Дубли, вложенные области, группы ногтей и посторонние предметы требуют разных
  проверок. Один NMS либо порог площади не решает все задачи.
- IoU недостаточно для вложенности: полезно направленное покрытие меньшей маски.
  Но даже полное покрытие не устанавливает, какая из двух областей ошибочна.
- Геометрия — источник признаков. Площадь, вытянутость, частичная видимость,
  число компонент или пересечение boxes сами по себе не разрешают удаление.
- Семантическая модель — кандидат для спорных случаев, её полезность неизвестна.
  Исторический Candidate J уже показал риск удаления целевых областей;
  он не завершил независимую оценку и не возобновлялся в этих опытах.

## Что показали тесты

Пилот:10 запросов (5 присутствующих товаров и5 отсутствующих записей),
83 каталожных товара,7 комбинаций трёх моделей,2 формулы. Один положительный
запрос повторяет каталожный снимок. Результаты диагностические, не holdout.

Ниже основная комбинация OpenCLIP+DINOv2+SigLIP2. Первая формула делит сумму
баллов на число областей запроса, вторая — на число назначенных пар.
Числители рассчитываются по одному оптимальному назначению.

| Этап | Top-1: первая / вторая | Top-10: первая / вторая | Что проверялось |
|---|---|---|---|
| Исходный пилот |1/5;1/5|1/5;3/5| Поиск на сохранённых автоматических масках |
| Удалены подтверждённые посторонние маски |1/5;2/5|1/5;3/5| Исключены4 маски: две одного кольца запроса, клей и кольцо конкурента |
| Исправлены маски обеих сторон |1/5;2/5|1/5;2/5| Приняты49 областей пяти положительных пар, удалён повтор, объединены части ногтя, добавлены пропуски |

Источники: [пилот](quality-pilot10-report.md),
[визуальный разбор](quality-pilot10-error-analysis.md),
[исключение постороннего](quality-pilot10-foreign-exclusion-report.md),
[исправленная разметка](manual-mask-experiment-report.md).

Очистка поставила розовый френч первым по второй формуле вместо4-го места.
По первой тот же пример опустился43→51: удаление ошибочной области меняет
не только содержимое, но и количество назначений и относительные scores.
Поэтому позиция поиска не может сама определять пригодность маски.

При последующей ручной коррекции вишни поднялись57→37 и нюд80→38 по первой
формуле, но оба остались вне top-10. По второй нюд опустился7→35:
вместо одной лучшей пары учитываются шесть, покрытие больше, среднее ниже.
Изолированная коррекция запросов изменила его парный ранг7→6; основное
расхождение связано с изменением каталожных областей. Вклад каждой новой
области по отдельности не измерялся. Ни одна комбинация не дала5/5 top-1.

Низкое разрешение — обоснованная гипотеза: четыре ожидаемых каталожных фото
имеют246×328 пикселей. Но опыт не менял исходники, поэтому причинность
низкого разрешения и эффект лучших оригиналов остаются UNKNOWN.

## Предлагаемые границы модуля

Это выводы для обсуждения, согласованные со смыслом существующих
[кандидатов правил](mask-filter-rule-candidates.md),
[черновика FR](mask-filter-functional-requirements.md) и
[вводных HLD](mask-filter-hld-inputs.md); их нормативный статус не повышается.

| Ответственность | Отношение к фильтру |
|---|---|
| Отобрать существующие пригодные маски отдельных ногтей; исключить подтверждённые дубли/группы/посторонние | Целевая возможность |
| Сохранить неопределённость и основания решения | Предлагаемый предохранитель; downstream-поведение ещё не выбрано |
| Найти пропущенный ноготь, исправить контур, объединить части | Отдельная локализация/коррекция, не простой отбор; ручной опыт включал эти вмешательства |
| Различить похожие дизайны и выбрать формулу рейтинга | Отдельные возможности сравнения и ранжирования |
| Сократить любое фото до10 областей | Не цель фильтра; корректные ногти нельзя отбрасывать ради лимита |

Архитектурный кандидат остаётся прежним: независимая политика и прикладной
сценарий внутри возможности локализации, адаптеры SDK/HTTP снаружи.
Отдельный микросервис не обоснован. Выполнять отбор нужно до отклонения
HTTP-ответа по выходному лимиту; сырые кандидаты ограничиваются по ресурсам
до попарного анализа. Согласованная обработка query/catalog, версия политики
и lineage необходимы для воспроизводимого сравнения. Формулы matching
для выделения модуля менять не требуется; их качество проверяется отдельно.

## Что ещё нужно проверить

Предлагаемый следующий шаг — независимая оценка именно отбора масок:

1. Зафиксировать критерий пригодности, допустимость смешанной маски,
   поведение UNCERTAIN и согласованные численные критерии качества.
   Одобрение пяти оранжевых областей относится к этому опыту,
   а не задаёт универсальное правило для всех частичных/фоновых ногтей.
2. Разметить физические ногти и пригодные/ошибочные кандидаты на разнообразных
   фото; разделить настройку и контроль по исходному фото/товару.
3. На сохранённых кандидатах сравнить baseline без отбора и прототип анализа
   геометрии/отношений; семантическую проверку добавлять как отдельную гипотезу.
4. Измерить сохранность уже найденных ногтей, ложные удаления, оставшийся мусор,
   дубли/группы, долю неопределённости, время и память. Общий recall локализатора
   с учётом пропусков показывать отдельно. Удаление дубля без потери ногтя
   не считать потерей целевого объекта.
5. После этого отдельно измерить поиск и влияние числа пар; порог отсутствия
   товара калибровать на соответствующих данных. В нынешнем пилоте он не задан,
   поэтому FPR и качество отказа не установлены.

Пока неизвестны достаточность геометрии, необходимость новой модели,
пороги и допустимые потери. Ручная очистка и коррекция не заменяют эти измерения.
Действующие модели, формулы, каталог и API данной сводкой не меняются.
