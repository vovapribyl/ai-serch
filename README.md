# Поиск ранее рассмотренных товаров и вариантов

Проект внутренней системы, которая помогает сотруднику найти ранее рассмотренный
товар по фотографии и доступным данным карточки. Один товар может встречаться
у разных продавцов, на разных площадках и под разными ссылками. Поиск должен
возвращать накопленную информацию, а окончательное решение оставлять человеку.

В репозитории собраны анализ предметной области, требования и код приложения.

## Задача и целевой сценарий

Проверка ссылок не позволяет уверенно найти тот же товар в другой карточке.
Сотруднику нужен способ сопоставить новый товар с историей рассмотрений.

Целевой процесс:

1. Сотрудник передаёт фотографию и доступные сведения о товаре.
2. Система ищет кандидатов в подготовленном корпусе — наборе товаров и фотографий.
3. Сотрудник изучает найденные записи, историю и статусы.
4. Человек определяет, найден тот же товар, его вариант или другая позиция;
   при недостатке данных результат остаётся неопределённым.

Это видение продукта, а не описание готовности всех возможностей.
В исходном MVP пользователь `CHECK` просматривает результат и не создаёт
или изменяет товарные записи. Границы и модель результата определены
в [Vision & Scope](docs/analysis/01-vision-and-scope.md).

## Что находится в main

Состояние проверено по исходному коду на 15 октября 2026 года.

| Часть | Содержимое этой ветки |
|---|---|
| Аналитика | Предметная область, сценарии, бизнес-правила, требования и критерии приёмки |
| Импорт корпуса | Чтение XLSX, проверка записей и изображений, подготовка и сохранение данных |
| Web-приложение | FastAPI, экран-заглушка с неактивной загрузкой фотографии и endpoint `/health` для проверки БД |
| Инфраструктура | Настройки, PostgreSQL с pgvector, миграции, файловое хранение и команды разработки |
| Проверки | Тесты компонентов приложения; наличие тестов не означает подтверждённый запуск всей системы |

В этой ветке пользовательский поиск по фотографии ещё не подключён.
Код импорта и наличие pgvector сами по себе не подтверждают готовность поиска.

## Разработка поиска и пополнения

Более поздняя реализация и результаты экспериментов опубликованы отдельно,
в ветке [codex/upload-optimiz](https://github.com/vovapribyl/ai-serch/tree/codex/upload-optimiz).
Её [README](https://github.com/vovapribyl/ai-serch/blob/codex/upload-optimiz/README.md)
содержит подробный статус и ссылки на отчёты.

В этой ветке ведутся работы по следующим направлениям:

- Локализатор товара возвращает маски областей; код обработки создаёт кропы.
- OpenCLIP, DINOv2 и SigLIP2 преобразуют кропы в векторы; алгоритм сравнения
  сопоставляет области и ранжирует кандидатов.
- Пополнение обрабатывает фото небольшими партиями, сохраняет результаты стадий
  и позволяет продолжить прерванную работу.
- Журналы, терминальный монитор и контроль ресурсов помогают разбирать остановки.

Эти компоненты не перенесены в `main`. Успешные отдельные испытания не означают
готовность всего продукта: оценка качества остаётся частичной, интеграция
с пользовательским поиском требует отдельной проверки.

## Локальная разработка

Базовый стек этой ветки: Python 3.12, FastAPI, PostgreSQL с pgvector, SQLAlchemy,
Alembic, Pillow и openpyxl. Зависимости описаны в [pyproject.toml](pyproject.toml),
команды — в [Makefile](Makefile), шаблон настроек — в [.env.example](.env.example).
Секреты и исходные данные не следует добавлять в Git.

Запуск базового приложения открывает экран-заглушку, описанный выше.
ML-окружение и модели из рабочей ветки не входят в эту базовую установку.
