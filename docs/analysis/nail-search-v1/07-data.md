## Логические связи

Товар → каталожные фото → выделенные области → производные обрезки → эмбеддинги по моделям. Запрос → фото пользователя → выделенные области → обрезки → эмбеддинги. В сравнении сохраняется связь результата с товаром и использованной парой фото.

| Данные | Необходимый смысл | Статус |
|---|---|---|
| Принадлежность | Область связана с исходным фото, фото — с товаром или запросом | Следует из выбранного процесса |
| Происхождение | Версия корпуса, Модуль выделения ногтей, подготовки обрезки, модели и её revision | Проектное предложение для воспроизводимости |
| Сопоставление | Использованные пары областей, отсутствие пары, оценка и итоговый ранг | Проектное предложение для анализа результатов |
| Состояние обработки | Различать успешную обработку, отсутствие областей и техническую ошибку | Проектное предложение; политика ошибок открыта |

Исходные фото не перезаписываются производными. Точные поля, идентификаторы, хранение масок, физическая схема, сроки хранения и активация версии — `UNKNOWN`, требуют проектирования. Сырые фото, маски, обрезки, эмбеддинги, IDs и приватные локаторы не добавляются в Git или публичные документы; действующие ограничения restricted сохраняются.

Все доступные ракурсы — граница желаемой подготовки, не утверждение об их наличии в текущем снимке. Перед запуском требуется безопасный агрегированный аудит доступности. Разрешения на получение новых внешних изображений этот документ не даёт.
