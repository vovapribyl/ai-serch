## Назначение и граница

Документ определяет, чем подтвердить готовность локального MVP. Компактная трассировка связывает группы бизнес-требований с правилами, функциями, данными, NFR и проверками. Промежуточные локальные ID и повторная трассировка к каждому источнику не создаются.

Техническая приёмка подтверждает выполнение функций и ограничений. Бизнес-эффект оценивают отдельно после измерения baseline; технический `PASS` не доказывает сокращение повторной работы.

## Проверки функционального сценария

| Требование | Проверка и ожидаемый результат | Свидетельство | Готовность критерия |
|---|---|---|---|
| `FR-001` | Пользователь запускает поиск без назначения и управления другими ролями | Результат сценарной проверки | Готов |
| `FR-002`, `FR-003` | С JPEG или PNG до 20 МБ поиск запускается; с нераспознаваемым, неподдерживаемым или превышающим 20 МБ файлом поиск не запускается и сообщает о необходимом входе | Два результата сценарной проверки | Готов |
| `FR-004` | На заранее размеченном недостаточном изображении продукт возвращает `UNCERTAIN`, а не `NEW` или `SAME_PRODUCT` | Входной пример, ожидаемая и фактическая выдача | Нужен размеченный пример |
| `FR-005` | Продукт показывает не более 10 кандидатов; `VARIANT` / `UNRELATED` применяются только для «Накладных ногтей», где утверждены правила; для `SAME_PRODUCT` отношение равно `N/A` | Набор пограничных примеров и фактическая выдача | Готов при наличии тестовых данных |
| `FR-006` | Для кандидата видны доступные статус и история; при `REJECTED_FOR_ASSORTMENT` без причины показан текст «Причина отклонения не определена» | Результаты двух сценарных проверок | Готов при наличии тестовых данных |
| `FR-007` | После любой проверки корпус, Google Sheets, карточка, статус, категория и роли не меняются | Сравнение состояния до и после | Готов |
| `FR-008` | После `UNCERTAIN` пользователь повторяет поиск с другой или дополнительной фотографией без системного лимита повторов MVP | Результат повторного сценария | Готов |
| `FR-018` | При конфликтующей истории продукт показывает все доступные записи и не выбирает одну автоматически | Результат проверки на конфликтном примере | Нужен размеченный пример |

## Проверки данных и качественных ограничений

| Условие | Проверка и ожидаемый результат | Свидетельство | Готовность критерия |
|---|---|---|---|
| Подготовленный снимок `ART-07` | Каждая допущенная запись имеет уникальный непустой `product_id` из цифр без ведущих нулей, `source_row`, категорию и одно основное изображение, встроенное в XLSX и однозначно связанное со строкой; второе фото не подменяет основное | Отчёт проверки снимка без раскрытия строк | Готов к проектированию теста |
| Полная замена корпуса | После ручной служебной загрузки поиск использует новый полный снимок; один товар сохраняет прежний `product_id` между перезагрузками; пользовательский интерфейс не предоставляет загрузку | Версии двух снимков, сверка стабильности ID и результат контрольного поиска | Готов к проектированию теста |
| Загрузка MVP | Проверенный XLSX `SRC-045` загружается служебной операцией: строки без категории или основного фото исключаются и отражаются в JSON-отчёте; повреждённый/нечитаемый XLSX или повтор `product_id` не заменяют действующий корпус | Версия снимка, результат загрузки и локальный JSON-отчёт | Готов к проектированию теста |
| XLSX 700 МБ | Представительный файл обрабатывается в согласованной среде | Отчёт с конфигурацией, временем, памятью и результатом обработки | Отложено до MVP 1.1 |
| Качество поиска | На 300 размеченных владельцем примерах «Накладных ногтей» проверяются: `SAME_PRODUCT Recall@10` не ниже 95%, `VARIANT Recall@10` не ниже 85% и ложный уверенный `SAME_PRODUCT` не более 5% | Версия выборки, правила разметки, расчёт и результат | Готов к проектированию теста |
| Время ответа | Не менее 80% запросов завершаются за 5 секунд от запуска поиска до показа результата на зафиксированной локальной машине | Версия корпуса, среда, границы измерения и распределение времени | Готов к проектированию теста |
| Ограниченный контур данных | Доступ имеют только владелец проекта и исполнитель MVP. Текущий корпус хранится до успешной замены, предыдущий удаляется после неё, JSON-отчёты хранятся 90 дней; данные не публикуют, не отправляют во внешние сервисы и не добавляют в Git без разрешения | Проверка состава поставки, места выполнения и сроков хранения | Готов для текущего локального контура |
| Ошибки загрузки и аудит | Отчёт содержит согласованные поля и записывается как локальный JSON на операцию; при технической ошибке поиска продукт не возвращает результат и не меняет данные | Пример отчёта загрузки и технической ошибки | Готов |

## Решение о готовности

MVP получает технический `PASS`, когда:

- пройдены все применимые функциональные критерии, проверки данных и качественных ограничений;
- для критериев с примерами подготовлены и зафиксированы входные данные;
- ни один применимый критерий не имеет статус «заблокирован»;
- установленные условия подтверждены фактическими результатами проверок; отложенный тест 700 МБ не входит в технический `PASS` MVP;
- правила выборки не применяют `VARIANT` вне утверждённых категорий;
- свидетельства позволяют повторить проверку на тех же версиях данных и правил.

До выполнения этих условий допустим технический прототип и исследовательские измерения. Они не считаются приёмкой MVP.

## Незакрытое покрытие

- Бизнес-эффект не принимается до выполнения отдельной задачи baseline `MEAS-001`.
- Полный корпус и промышленная инфраструктура не входят в приёмку локального MVP.
- MVP 1.1 с обменом Google Sheets требует отдельного набора требований и критериев.
- Ручная обрезка объекта перенесена в [бэклог](functional-backlog.md).
