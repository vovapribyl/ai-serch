## Что уже нормативно установлено

- Продукт помогает проверить, рассматривался ли товар ранее, возвращает кандидатов и историю; окончательное решение принимает человек.
- Результат запроса: `NEW / SAME_PRODUCT / UNCERTAIN`; отношение к отличающемуся кандидату: `VARIANT / UNRELATED`; для `SAME_PRODUCT` — `N/A`. `ANALOG` исключён.
- В MVP действует одна продуктовая роль `CHECK`. Менеджер и руководитель работают во внешнем процессе; поставщик не участвует в продукте.
- `NEW` — результат поиска, а не статус записи. При `NEW` пользователь может вручную вне продукта внести товар в Google Sheets. Продукт в MVP статусы только показывает и не создаёт или не меняет записи.
- Начальный корпус MVP — ногтевой поднабор. Детальные правила сопоставления действуют только для «Накладных ногтей»; вне поднабора поиск возвращает только `NEW` или `UNCERTAIN`, а для остальных категорий поднабора правила ещё не определены.
- Текущая таблица — источник AS-IS, а не спецификация будущей системы. Финансовые формулы вне scope.
- Полный корпус включает рабочую таблицу, действующий ассортимент, архивы рассмотрений и доступные фотографии; на первом этапе допустима однократная выгрузка.
- Уже переданный рабочий `SRC-045` загружают один раз полным XLSX-снимком вне пользовательского интерфейса. `product_id` назначен командой аналитиков; номер строки — локатор этого снимка. Поиск использует одно основное встроенное фото.
- Бизнес-требования находятся в [`ART-01`](01-vision-and-scope.md), бизнес-правила — в [`ART-05`](05-business-rules.md), сценарии и функциональные требования — в [`ART-06`](06-user-scenarios-and-functional-requirements.md) v0.8 `APPROVED_BY_OWNER` (`SRC-053`).
- По `DEC-059` новый снимок и плановая перезагрузка корпуса не входят в MVP. Повтор технической попытки допустим только до успешной первоначальной загрузки того же `SRC-045`.
