# Единый quality gate облегчённого пакета `ART-08`–`ART-10`

> [Индекс review](README.md) · [`ART-08`](../08-non-functional-requirements.md) · [`ART-09`](../09-acceptance-criteria-and-traceability.md) · [`ART-10`](../10-risks-assumptions-and-open-questions.md)

## Короткий план-контракт

**Цель:** закрыть оставшиеся контракты аналитического пакета минимальным содержанием, необходимым для разработки и доказательной приёмки локального MVP.

**Входы:** утверждённые `ART-01`–`ART-07`, действующие `DEC-*` и `GAP-*`, решение владельца `SRC-047` / `DEC-055`.

**Границы:** один компактный документ на контракт; одна общая проверка; без переписывания утверждённых артефактов, полного повторения источников, новых пространств ID и отдельных матриц для каждого уровня.

**Запрещённые выводы:** не придумывать SLA, архитектуру, владельца данных, права доступа, методику метрик или критерии прохождения теста 700 МБ. Не считать технический `PASS` доказательством бизнес-эффекта.

**Ожидаемый результат:** `ART-08` содержит критичные ограничения и `UNKNOWN`; `ART-09` связывает существующие требования с проверками и свидетельствами; `ART-10` показывает активные риски поверх канонических `GAP-*`.

**Самопроверка:** границы контрактов, точность решений и неизвестных, отсутствие новых требований и новых пространств ID, локальные ссылки, Markdown, конфликтные маркеры и `git diff --check`. Новый `GAP-*` допустим, если он фиксирует обнаруженный разрыв без принятия решения за владельца.

## Результат авторской проверки

`PASSED` — 2026-08-31 проверены:

- границы контрактов `ART-08`–`ART-10` и отсутствие архитектурных решений;
- точность `DEC-006`–`DEC-008`, `DEC-050`, `DEC-053`–`DEC-055` и сохранение `UNKNOWN`;
- существование всех упомянутых `SRC-*`, `DEC-*`, `GAP-*` и `FR-*`;
- локальные ссылки и одинаковое число колонок в строках Markdown-таблиц;
- отсутствие новых пространств ID, конфликтных маркеров и ошибок `git diff --check`.

Технические тесты продукта не запускались: реализация ещё не начата. Авторская проверка подтверждает целостность документов, а не выполнение критериев MVP.

## Результат независимого review

Первичное review — `REWORK`: 0 Critical / 4 Major / 2 Minor. Reviewer не редактировал файлы.

Исполнитель исправил Major:

- добавил компактную групповую трассировку `BG → ART-05 → FR / данные / NFR → проверка`;
- потребовал для технического `PASS` фактически пройти все применимые функциональные, data- и NFR-проверки;
- добавил проверку встроенного изображения, связи со строкой и стабильности `product_id` между перезагрузками;
- вернул тип и статус активных вопросов, а неподтверждённых владельцев ответа обозначил `UNKNOWN`.

Minor также обработаны: синхронизирован следующий gate, исправлен паспорт `ART-06`, а непокрытые ручная обрезка и лимит десяти кандидатов из `DEC-006` вынесены в `GAP-012` для явного решения владельца.

Повторное независимое review — `REWORK`: 0 Critical / 0 Major / 2 Minor. Reviewer подтвердил закрытие всех первоначальных Major и не редактировал файлы.

Исполнитель исправил Minor:

- добавил `FR-002` / `FR-003` в групповую сквозную трассировку;
- уточнил, что самопроверка запрещает новые требования и пространства ID, но не запрещает обоснованный `GAP-*` в действующем пространстве.

Финальная авторская проверка после Minor — `PASSED`. По governance ещё одно независимое review не требуется. Итог пакета — `READY_FOR_OWNER_GATE`; это не owner approval и не подтверждение выполнения тестов продукта.

## Следующий gate

После обработки замечаний весь пакет передаётся владельцу на одно явное утверждение. До него `ART-08`–`ART-10` не считаются утверждёнными входами для зависимого этапа.
